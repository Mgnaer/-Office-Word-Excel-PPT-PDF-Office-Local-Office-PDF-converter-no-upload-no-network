=========================================================
  WP互相转换工具  ——  Office(Word/Excel/PPT) ⇄ PDF 转换器
=========================================================

【软件简介】
  本工具调用本机已安装的 Microsoft Office 组件（Word / Excel / PowerPoint）
  直接做格式转换，由各自应用的排版引擎输出，保真度最高。
  PDF 的反向转换借助 Word 的 PDF 重排能力。
  无需联网、无需任何第三方 Python 库。

【支持的转换】

  ── 第一档：保留排版（推荐）──
  · Word   → PDF ：.docx / .doc / .docm / .dotx / .rtf
  · Excel  → PDF ：.xlsx / .xlsm / .xlsb / .xls
  · PPT    → PDF ：.pptx / .pptm / .ppsm / .ppsx / .ppt / .pps
  · PDF    → Word：.pdf → .docx（Word 的 PDF 重排引擎重建段落，可继续编辑）
    这一档都是各应用自己的排版引擎输出，视觉效果与原件一致。

  ── 第二档：内容级重建（提取内容，不是版式还原）──
  · PDF    → PPT ：.pdf → .pptx
  · PDF    → Excel：.pdf → .xlsx
    Excel 和 PowerPoint 的接口无法直接打开 PDF，因此这两个方向的做法是：
    先用 Word 把 PDF 重排成中间 DOCX，再把段落 / 表格 / 图片按页重组进
    PPT / Excel。文字、表格、图片都会保留，但原有的精确位置、字体、
    配色不会完整还原；扫描件（纯图片 PDF）只能得到图片。
    另需注意：Word 的 PDF 重排并不总能识别出表格结构 —— 小表格通常能还原成
    多列网格，但较大的表格经常被压平成一行文本（多列内容用空格连在一起）。
    这是上游重排引擎的限制，不是本工具的解析问题。
    适合「从 PDF 里提取内容到 Office 再编辑」，
    不适合「PDF 原样转成 PPT」这类要求版式一致的场景。
    PDF 的输出目标在界面右上角「PDF 转换为」里选择
    （Word / PPT（仅内容）/ Excel（仅内容）），切换后会同步更新列表里的 PDF。

  说明：Word / Excel / PPT 三种类型直连各自的 Office 应用，
        同类型文件在批量转换时会复用同一个应用实例（快）；
        不同类型混排时会各自保持一个实例。

【使用方法】
  1. 双击桌面上的「WP互相转换工具」快捷方式（或本文件夹内的
     「启动WP互相转换工具.bat」）。
  2. 点「＋ 添加文件」选择文件，或用「添加文件夹」批量导入。
     方向由扩展名自动识别：Word/Excel/PPT 文件 → 转 PDF；
     PDF 文件 → 按右上角「PDF 转换为」所选目标（Word / PPT / Excel）转换。
  3. 选择输出位置：默认「输出到源文件所在目录」，也可指定统一目录。
  4. 点「▶ 开始转换」，等待进度完成。
  5. 结果不覆盖原文件；同名时自动加 (1)(2) 后缀。

【运行环境】
  · Windows + Microsoft Office：
      · Word 2013 及以上 —— 转换 Word 与读取/重排 PDF 必需
      · Excel / PowerPoint —— 转换对应类型，以及 PDF → PPT / Excel
  · Python 3，不依赖任何第三方 Python 库。
  · 若未安装 Office，可安装 LibreOffice 作为备用引擎
    （仅支持各类文件 → PDF；PDF → Office 方向需要 Microsoft Office）。

【Word 转 PDF 的底层逻辑（简述）】
  Word 文档(.docx)本质是一个 ZIP 包，内部是 OOXML 格式的 XML
  描述（文字、样式、段落、页面设置等），它只是“内容描述”，不含
  最终版面。PDF 是“页面描述语言”，保存每一页最终的坐标、字形、
  线条——即固定版面。所以 Word→PDF 的核心是“排版引擎把 OOXML
  渲染成固定版面”，主流有三种实现：
    1) Word COM 自动化：调用 Word 自己的排版引擎并
       ExportAsFixedFormat 导出 PDF —— 保真度最高（本工具采用）
    2) LibreOffice 无头模式：soffice --convert-to pdf
    3) 纯代码渲染库：自己解析 OOXML 再生成 PDF（复杂、保真度低）
  反向 PDF→Word：Word 2013+ 用 PDF 重排引擎解析固定版面，重建
  可编辑文档流（文字→段落、图片保留），再 SaveAs 为 .docx。

  PDF → PPT / Excel 的做法（内容级重建）：
  由于 Excel 与 PowerPoint 都不支持打开 PDF，本工具先用 Word 把 PDF
  重排成 DOCX，再解析其中的正文段落、表格结构和图片，分别重建：
    · PPT  ：按 PDF 分页切成幻灯片；过长的段落按句切分；表格单独成页；
             图片等比缩放后单独成页。
    · Excel：保持文档顺序。若重排保留了表格结构，会还原成多列单元格网格；
             若表格被压平，则按行输出文本（大表常见这种情况）。

【常见问题】
  · 首次把 PDF 转 Word 时，Word 可能弹出「将 PDF 转换为可编辑
    文档」提示。本工具已自动勾选「不再显示此消息」；万一出现，
    点「确定」即可，之后不再提示。
  · 提示「未检测到 Microsoft Word」→ 请安装 Word 后重试。
  · 转换大文件/复杂文档可能需要数十秒，请耐心等待。
  · 请勿在转换过程中手动结束 Word 进程。

【下载后完整性校验（重要）】
  本工具通过 zip / 网盘等方式传播时，下载的文件可能被中间人替换或损坏。
  发布包附带 SHA256 校验清单；启动器「启动WP互相转换工具.bat」现在会
  在每次启动前自动校验，校验不通过会直接拒绝启动。

  也可以单独手动校验（不启动工具）：
    双击「校验文件完整性.bat」，或在命令行执行：
      powershell -NoProfile -ExecutionPolicy Bypass -File verify_hashes.ps1
    全部显示 [ OK ] 即可放心使用。

  ── 信任链的边界（请务必理解）──
  清单文件 SHA256校验清单.txt 自己也在包里。如果攻击者能同时替换
  “文件”和“清单”，上面的校验会全部通过 —— 这不是 bug，而是所有
  包内哈希清单的固有局限。
  因此：清单文件本身的 SHA256 必须从【发布页 / 提供者】处获取并核对：
      certutil -hashfile "SHA256校验清单.txt" SHA256
  只有发布页公布的值与本地一致时，这份清单才具备可信度。

  校验范围：所有会被执行的脚本与批处理（bootstrap / 转换引擎 / 弹窗守护 /
  主程序 / 校验脚本 / 两个 .bat）。「使用说明.txt」属于文档、不参与校验 ——
  这样你可以自由在说明里加笔记，不会因此导致启动被拦。

  手动核对单个文件也可用：
      certutil -hashfile "文件名" SHA256

【v2.1 更新（新增 PDF 转 PPT / Excel）】

  · 技术限制与实现方式：Excel 和 PowerPoint 的 COM 接口都不能直接打开 PDF
    （只有 Word 具备 PDF 重排能力）。因此这两个方向采用两阶段“内容级重建”：
        PDF ──Word 重排──▶ 中间 DOCX ──解析──▶ 段落/表格/图片 ──▶ PPTX / XLSX
    · PPT：按 PDF 的分页切成幻灯片；长段落按中文句末标点拆成多行；

    · Excel：按文档顺序写入；表格还原成真实单元格网格（多列），文字每段一行。
  · 请注意：这两个方向是“内容级重建”，不是版式级还原。文字、表格、图片都会保留，
    但原有的精确位置、字体、配色不会完整还原；扫描件（纯图片 PDF）只能得到图片。
  · 界面新增「PDF 转换为」选择器（Word / PPT / Excel），切换时同步更新已加入的 PDF。
  · 混合批次支持 4 种模式共存，各自复用对应的 Office 实例。
